# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build

.NET Framework 4.8 / WinForms solution using the new `.slnx` format (`CustomTools.slnx`), no `.sln` file. Build with MSBuild or Visual Studio — there is no `dotnet build` support (classic `Microsoft.CSharp.targets`-based csproj, not SDK-style).

```
msbuild CustomTools.slnx /p:Configuration=Debug
```

`msbuild` is not on PATH in this environment; locate it with `Get-ChildItem "C:\Program Files\Microsoft Visual Studio" -Recurse -Filter MSBuild.exe` (found at `...\18\Community\MSBuild\Current\Bin\MSBuild.exe` on this machine).

There are no test projects and no lint config in this repo.

`CTRegistryTree` builds its output directly into `CustomTools/bin/Debug/Plugins/` (see its `OutputPath` in Debug config) so the host app picks it up as a plugin without a manual copy step. Release builds do not have this redirect — output goes to the project's own `bin\Release\`, so it won't be discovered by the host in a Release run unless copied to `Plugins/` manually.

## Architecture

CustomTools is a Windows system-tray application (`CustomTools/Program.cs`) with no main window: it creates a `NotifyIcon` and builds its context menu dynamically from plugins. The solution is split into three projects that form a plugin host/plugin-API/plugin-implementation chain:

- **CustomTools** (`WinExe`, entry point) — the tray host. References `CTPlugins` only, never plugin implementations directly. `Program.cs` builds one `ContextMenuStrip`, rebuilding its `Items` from every plugin's `GetMenuItems()` on each `Opening` event (so registry-backed changes show up without a restart), then appends its own Options/Exit entries. It also owns two host-only features that plugins never touch: `FrmOptions` (a `FrmTemplateDialog` subclass) and `StartupManager`, which toggles launch-at-login via the `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value.
- **CTPlugins** (`Library`) — the plugin contract, shared by the host and every plugin:
  - `ICTPlugin` — interface every plugin implements (`Name`, `GetMenuItems()` returning `ToolStripItem[]`).
  - `CustomToolsPluginAttribute(name, version)` — marks a class as a discoverable plugin.
  - `CTPlugins.FindPlugins()` — scans the `Plugins/` folder next to the host EXE, `Assembly.LoadFile`s every `*.dll`, reflects over types for the attribute, and `Activator.CreateInstance`s each as `ICTPlugin`. This is how new plugin assemblies get picked up — no registration list to edit.
  - `FrmTemplateDialog` — base dialog form with `OKClicked`/`CancelClicked` events; plugin dialogs (e.g. `CTRegistryTree`'s manage-item forms) and host dialogs (`FrmOptions`) derive from this instead of `Form` directly.
  - `GroupLabelRenderer` — a `ToolStripProfessionalRenderer` the host installs on the tray's `ContextMenuStrip` so each plugin's contiguous run of items (tagged with a shared `ToolStripItem.Tag`, e.g. `CTRegistryTree` stamps `item.Tag = Name` on everything it returns) gets a rotated section label drawn in the native image-margin column. It exists because `ToolStripDropDownMenu` recalculates and overwrites `Padding` on every layout pass, so the margin column is the only reservation that survives — read the type's doc comment before changing menu layout/rendering, it records several rendering approaches that were tried and silently fought by the framework.
- **CTRegistryTree** (`Library`) — the one real plugin, and the reference implementation for writing new ones. Persists its menu items under `HKCU\SOFTWARE\Appit\CustomTools\Items` and rebuilds `ToolStripItem[]` from that registry key each time `GetMenuItems()` is called. `RegistryTreeItem` defines explicit conversion operators to/from `RegistryKey` and `TreeNode` to move data between the registry, the model, and the WinForms `TreeView` UI in `FrmManageItemsForm`/`FrmManageItemForm`.

To add a new plugin: create a `Library` project referencing `CTPlugins`, implement `ICTPlugin`, tag the class with `[CustomToolsPlugin(name, version)]`, and set its Debug `OutputPath` to `..\CustomTools\bin\Debug\Plugins\` (matching `CTRegistryTree`'s pattern) so the host discovers it.

### Localization

Every project (`CustomTools`, `CTPlugins`, `CTRegistryTree`) carries a neutral `Properties/Strings.resx` plus satellites for `pl`, `de`, `es`, `it`; .NET resolves the culture-matching resource automatically via the generated `Strings.Designer.cs`.

**`Strings.Designer.cs`/`Resources.Designer.cs` are NOT auto-regenerated by `msbuild`** — `ResXFileCodeGenerator` is a Visual Studio design-time single-file generator, not an MSBuild build step. When adding a new resource key: add it to the neutral `.resx`, hand-add the matching property to the `.Designer.cs`, then add translated values to every satellite `.resx`.

Old-style (non-SDK) `.csproj` files also require every new `.cs`/`.resx` file to be added explicitly as a `<Compile>`/`<EmbeddedResource>` item — there's no implicit glob inclusion.

`CustomTools` has a `LanguageManager` (`CustomTools/LanguageManager.cs`) letting the user pick a language in Options, persisted at `HKCU\SOFTWARE\Appit\CustomTools\Language` (empty = OS default) and applied via `Thread.CurrentThread.CurrentUICulture` — takes effect immediately, no restart, since menu items and dialogs re-read `Strings.*` each time they're built.

## Releasing

`CustomTools/Resources/License.rtf` is a static RTF copy of the repo's `LICENSE.txt`, embedded via `Properties/Resources.resx` (`Resources.LicenseRtf`) and shown in the About → License dialog for offline viewing (it also tries to fetch the live `LICENSE.txt` from GitHub at runtime). **Whenever a new version is published to GitHub, regenerate `License.rtf` from `LICENSE.txt`** if the license text changed:

```python
lines = open("LICENSE.txt", encoding="ascii", newline=None).read().split("\n")
esc = lambda l: l.replace("\\", "\\\\").replace("{", "\\{").replace("}", "\\}")
body = "\n".join(esc(l) + r"\par" for l in lines)
rtf = r"{\rtf1\ansi\ansicpg1252\deff0\deflang1033{\fonttbl{\f0\fmodern\fprq1\fcharset0 Consolas;}}\viewkind4\uc1\pard\f0\fs18" + "\n" + body + "\n}"
open("CustomTools/Resources/License.rtf", "w", encoding="ascii", newline="\r\n").write(rtf)
```

Also bump `AssemblyInformationalVersion` in all three `AssemblyInfo.cs` files and the tray tooltip string in `Program.cs`.
